## R2 · Edge-case checklist (project-specific)

**Size**
- 0 skills (missing dir, existing empty dir) · 1 skill · typical 5–20 · 200 · 1,000
- List longer than viewport (scroll window; cursor top/middle/bottom) · preview longer than viewport
- Terminal 20×10, 50×20, 70×24, 80×24, 80×10, 120×40, 200×60

**Content**
- Missing `SKILL.md` · empty `SKILL.md` · body-only file · file starting with `---` (thematic break)
- UTF-8 BOM before `---` · CRLF · unterminated frontmatter · invalid YAML
- Description with a newline (folded) · with a tab · 400 chars · frontmatter name ≠ dirname
- Skill name in CJK · emoji name · name containing a control byte
- `metadata.category` as scalar, list and map
- Body containing `\e[2J`, OSC-0 title set, OSC-52 clipboard

**Boundaries**
- cursor at 0 / last / empty list · pgdown past end · `G` on empty list
- `vis = contentH(h)` at h = 5, 6, 10 · preview wrap width 20 vs box inner 14
- width exactly 70 (the `m.width < 70` breakpoint) · width 36, 37 (header title + right hint)

**State**
- delete → undo → delete again inside 30 s · undo with nothing pending · undo after the name reappeared
- `r` rescan while the spinner chain is stopped · `e` edit then immediate `j` · resize during a scan
- `/` filter → 0 matches → Esc Esc · `:` unknown command · `:` empty + Enter
- help open then `d` · confirm open then `r` · preview focused then `d`/`u`/`g`/`G`
- toast replaced 1 s later · undo timer firing after a newer delete

**Timing**
- scan < 100 ms (spinner must not flash) · scan > 1 s (cancel with Esc) · toast at 3 s and 3.5 s · undo at 30 s
- two deletes in the same second · 400 rapid keypresses · resize storm

**Environment**
- non-TTY stdin · non-TTY stdout · `TERM=dumb` on a real TTY · `NO_COLOR=1` · `CI=1` · `REDUCED_MOTION=1` · `NO_ANIMATIONS=1`
- `$EDITOR` unset / `EDITOR=true` / `EDITOR="code -w"` / `EDITOR="'/path with space/vi'"`
- `HOME` unset · relative `XDG_CONFIG_HOME`/`XDG_DATA_HOME` · skills dir on a different filesystem than the data dir
- `SKILLMAN_SKILLS` unset / empty / `~/tilde` / a file instead of a dir

**Failure**
- skills dir unreadable · `SKILL.md` unreadable · trash dir unwritable · disk full mid-copy
- scan error after a successful scan · editor binary missing · rescan error after delete/undo
- `os.Rename` → `EXDEV` · `os.RemoveAll(src)` failing after a successful copy

**Multiplicity**
- two `skillman` processes on one dir · external `rm -rf` of a listed skill · TUI delete then CLI delete

**Compatibility**
- skills dir written on Windows (BOM/CRLF) · frontmatter with unknown extra keys · `metadata` as list not map
- future: old `state.json` + new binary (not yet built)

**Presentation**
- 80×24 reference frame · narrow collapse < 70 · help modal at height 24/18/12/10 · confirm modal
- empty dir vs no-match vs loading vs error · `NO_COLOR` (no colour-only meaning) · selected-row indicator without colour

## R3 · Findings

Every defect is labelled **(confirmed)** = reproduced by running code, or **(suspected)** =
found by reading only, with the reason it could not be reproduced.

### A · Correctness

**A1 · `lipWidth` counts runes, not display cells — CJK/emoji destroy the frame (confirmed)**
`view.go:426` uses `utf8.RuneCountInString`; `truncate` (`view.go:388`), `truncRunes`
(`view.go:401`) and `padRight` (`view.go:415`) all inherit the error.
Repro — skill named `日本語スキル名` at 80×24:

```
P6 CONFIRMED row: 38 cells > pane 31
P6 CONFIRMED: view line 4 = 92 cells > 80
P6b CONFIRMED: line 4 = 84 cells
```

Nine 🎉 in a name → 43 cells in a 31-wide pane. Every `+---+` border and `|` is destroyed.
Affects anyone with non-Latin skill names — likely in a skills repo.
**Fix:** `lipWidth = runewidth.StringWidth(stripANSI(s))` (already an indirect dep of
bubbles — promote it), then add a golden test asserting cell width, not rune count.

**A2 · The styled header is never truncated — frame wraps below 37 columns (confirmed)**
`view.go:46-53` builds `title + gap + right` with `gap` floored at 1. The plain branch
truncates (`view.go:44`); the styled branch does not.

```
width=20 header width=37   width=30 header width=37
width=34 header width=37   width=40 header width=40
```

`"SkillMan  25/25 skills ?help  /search"` is 35 cells in a 20-column terminal → the whole
frame shifts down a row on every redraw. This is audit **B16**, still unfixed.
**Fix:** `return truncate(t+strings.Repeat(" ",gap)+r, m.width)`, or drop the right hint below 48 cols.

**A3 · `validate`'s exit code depends on alphabetical order (confirmed)**
`cli.go:103-112` returns from inside the loop on the *first* invalid skill.
Repro — `aaa-warn` (missing name) + `zzz-err` (no `SKILL.md`):

```
1 ok, 1 warn, 1 err (2 total)
P9 CONFIRMED: exit 1; contract '2 = missing SKILL.md' is order dependent
```

`cli_test.go:53` only covers the case where the error skill happens to sort first, so the
suite hides this. Scripts gating on exit 2 get the wrong answer.
**Fix:** compute max severity over all issues, then map once to the exit code.

**A4 · Two sources of truth for severity, coupled by an English string (confirmed)**
`skills.go:111` sets `Valid`; `skills.go:183-193` re-derives the badge and decides `err` by
`strings.HasPrefix(is, "missing SKILL.md")`. Rewording that string silently changes exit codes.
**Fix:** `type Issue struct{ Code, Msg string; Sev Severity }`; `Valid` and `Badge` both read `Sev`.

**A5 · Frontmatter detection is a naive prefix match (confirmed)**
`skills.go:120` `strings.HasPrefix(raw, "---")` matches `----`, `---abc` and a markdown
thematic break, and misses a UTF-8 BOM. Repro:

```
skill bom    valid=false issues=[missing description missing name]
skill plain  valid=false issues=[invalid frontmatter: unterminated frontmatter (missing closing ---) missing description missing name]
```

**Fix:** require the first line to equal `---` after trimming an optional BOM; treat
"no frontmatter" as a distinct outcome from "malformed frontmatter".

**A6 · Audit B12's fix is only half-done (confirmed)**
`skills.go:74-92` appends `invalid frontmatter: …` **and then still** appends `missing name`
and `missing description`, so a malformed file is reported with two extra lies:

```
- ctrl: invalid frontmatter: yaml: control characters are not allowed; missing description; missing name
```

**Fix:** return early from issue collection on a parse error — the parse error is the whole story.

**A7 · `help` as a positional shadows a skill named `help` (confirmed)**
`main.go:27-29` returns help *during flag scanning*, before subcommand dispatch.
Repro — `run(["delete","help","--yes"])` printed the help text and exited 0; the skill was
untouched. Same for `view help`, and for any skill named `-h`.
**Fix:** drop the bare `help` positional (or require it as `positional[0]`) and honour `--`.

**A8 · `install` overloads exit code 3 and points at a doc slated for deletion (confirmed)**
`main.go:84-86` returns 3 — the same code as "destructive action refused" — and its message
says "see PLAN.md Phase 5". `PLAN.md:120` (Phase 12) plans to delete `PLAN.md`. Extra args
to `install` are silently ignored.
**Fix:** exit 4 for "unimplemented", or remove the stub; never reference a file you plan to delete.

**A9 · `--skills-dir=` with an empty value is silently ignored (confirmed)**
`main.go:46-47` stores `""`, and `main.go:56` exports only when non-empty → the default dir
is used with no warning. Repro: `run --skills-dir= list -> exit 0 (no error, default dir used)`.
**Fix:** reject an empty value with exit 2. Related, also confirmed: `--json` is accepted but
ignored by `view`/`delete` (`main.go:34-35`), and `view a b c` silently drops `b c`.

**A10 · Preview scroll is destroyed by any list cursor move (confirmed, live)**
`model.go:161-178` — `refreshPreviewAt(true)` calls `GotoTop()`; `update.go:291` (`move`),
`update.go:219-229` (`g`/`G`/`home`) and `applyFilter` (`model.go:151`) all route through it.
Repro — probe `preview YOffset before move=5 after move=0`; live tmux after `G` (showing body
line 105) then `Tab` `j` → back at line 1. The Phase 10 fix covers only *resize*; this is the
far more common path.
**Fix:** keep a `map[skillName]scrollOffset`, or reset only when the selected name changes.

**A11 · The preview cache is not invalidated by the delete/undo rescans (confirmed)**
`update.go:37` calls `invalidatePreview()` on `skillsLoadedMsg`, but `doDelete` (`update.go:336`)
and `doUndo` (`update.go:359`) reassign `m.skills` and call `applyFilter` **without** it. The
cache key is name+width only (`model.go:189`). Repro: `cache content: v1=true v2=false` after a
delete/undo cycle where the file changed on disk.
**Fix:** funnel delete/undo through the same `skillsLoadedMsg` reload path.

**A12 · `renderPreviewBox` writes to a value copy (confirmed by inspection)**
`view.go:167` `m.preview.Width = w - 4` inside `func (m Model) renderPreviewBox` is discarded.
The numbers agree today only because `previewWidth()` (`model.go:230`) independently recomputes
the same formula. Any change to one silently desynchronises the glamour wrap width from the box —
a repeat of the B2 bug class.
**Fix:** one `layout` struct computed once from `(w,h)` and passed to both.

**A13 · `ScanSkills` skips symlinked skills and swallows walk errors (suspected)**
`skills.go:51` uses `e.IsDir()`, which is `lstat`-based, so `skills/mylink -> ../elsewhere` is
invisible. `skills.go:101-106` returns `nil` from the walk callback on error, so unreadable
subtrees count as 0 bytes with no issue recorded. Could not construct either case on Termux.

### B · Robustness and data safety

**B1 · `doDelete`/`doUndo` do a full synchronous rescan inside `Update` (suspected — code path)**
`update.go:336` and `update.go:359`. On slow storage or with 1,000 skills, `y` freezes the UI,
violating `tui-philosophy.md:38`. Local scans are ~5 ms so no freeze was observable here.
**Fix:** emit a `reloadCmd()` and let `skillsLoadedMsg` land.

**B2 · Both rescans discard their error (confirmed by inspection)**
`update.go:336,359` `skills, _ := ScanSkills(...)`. A transient error yields `nil` → the list
silently empties while the status bar still claims the skill was deleted.
**Fix:** handle the error and toast it.

**B3 · The cross-device move fallback is not atomic (suspected)**
`trash.go:70-74` — after a successful `copyDir`, `os.RemoveAll(src)` can fail partway, leaving
the skill split across two locations with no record of the second half. `trash.go:71` does
`os.RemoveAll(dst)` on copy failure, which is safe only because the destination was proven
unique. Not reproducible without two filesystems.
**Fix:** copy to `<dest>.partial`, fsync, rename into place, then remove the source; log the
split if removal fails.

**B4 · `undoDelete` is stat-then-rename with no inter-process lock (confirmed for the benign case)**
`trash.go:49-54`. The benign path errors correctly:
`delete of a vanished skill errors as expected: rename …: no such file or directory`.
The TOCTOU window and two-process races remain.
**Fix:** `os.OpenFile(dest, O_CREATE|O_EXCL)` as a restore lock; detect concurrent instances.

**B5 · Refusing to undo strands the user (confirmed)**
`trash.go:50` returns `"%s exists again — not restoring (left in trash at %s)"`. That path is
truncated in the status bar and there is no `trash` command, so recovery requires knowing the
internal directory layout.
**Fix:** add `skillman trash list|restore|purge` — pull Phase 11 forward for this.

**B6 · The log grows without bound and records absolute paths (confirmed)**
`config.go:73-85` appends forever with no rotation. `trash.go:40,55` log the full trash path,
i.e. the user's home layout. The trash itself also grows without bound.
**Fix:** size-based log rotation; log skill names only; `trash purge --older-than`.

**B7 · `trashDir` is created 0o755 (suspected)**
`trash.go:24`. Here it came out 0700 because Termux's umask is 077; on a default-umask host
the deleted skill content is world-readable. **Fix:** `0o700` explicitly.

### C · Security and privacy

**C1 · Terminal escape injection from untrusted skill content (confirmed)**
Skill files are third-party input. Nothing filters C0/C1 bytes.
Repro — `skillman view body-esc --plain | cat -v`:

```
normal line
^[[2J^[[1;1H CLEARED SCREEN ^[]0;PWNED^G
another
```

`ESC[2J` clears the screen, `ESC[1;1H` homes the cursor, `OSC 0` renames the window. With
`OSC 52` a malicious skill could rewrite the user's clipboard. `skillman list` emits a raw TAB
from a directory name (the dirname is not YAML, so it is fully attacker-controlled).
In the **TUI** the glamour path happens to escape body bytes (the live frame showed the literal
text `[2J1;1H CLEARED`), but the **row and status** paths do not — confirmed:
`row="> evil\x1b[31mRED\x1b[0m  [ok]"` and `status="evil\x1b[31mRED\x1b[0m · d  |  normal"`.
**Fix:** one `sanitize(s)` applied to every untrusted string (name, desc, category, issue text,
body) stripping `\x00-\x08\x0b-\x1f\x7f` and escaping `\x1b`; call it in `ScanSkills` at the
boundary so the TUI, the CLI and the JSON output are all covered.

**C2 · `os.Setenv` mutates process state from a flag (confirmed by inspection)**
`main.go:57` exports `SKILLMAN_SKILLS`, which then wins over every other lookup for the rest of
the process. Harmless today, but it makes config precedence (`--skills-dir` > env > XDG > home)
implicit across two files.
**Fix:** resolve the skills dir once in `run()` and pass it explicitly.

**C3 · Dependency and supply-chain notes (confirmed)**
- `go.mod:9` pins `lipgloss v1.1.1-0.20250404203927-76690c660834`. `go list -m -versions` shows
  the newest tag is **v1.1.0** — an unreleased commit with no upstream release and no recorded
  reason. Pin `v1.1.0` unless a specific upstream fix is load-bearing, and say which in a comment.
- `go.mod:1` `module skillman` is not a resolvable path, so `go install <url>@latest` cannot
  work and the module cannot be vendored by consumers.
- No `govulncheck` in CI. Nothing is known-vulnerable and `go mod tidy -diff` is clean, but there
  is no check.

**C4 · `logf` is silent on failure and writes to a shared append-only file (confirmed by inspection)**
`config.go:76-79` swallows the open error. With two instances, interleaved partial lines are
possible. Low impact.

### D · Performance and efficiency

**D1 · Rescan cost is dominated by work nothing consumes (suspected)**
`skills.go:100-107` runs a full `filepath.Walk` of every skill directory to compute `Size`,
which is **never read anywhere** (`rg '\.Size'` returns only the assignment). `ModTime` is
likewise never displayed. Every `r`, every post-edit reload and every delete/undo pays a full
tree walk for a discarded number.
**Fix:** delete `Size`, `ModTime` and the walk, or surface them in `list`/`validate`.

**D2 · Every `SKILL.md` body is retained in RAM (suspected)**
`skills.go:61,73` read and keep `Body` for every skill; `previewCache` (`model.go:97`) then holds
a *second*, glamour-rendered copy per visited skill. 200 skills × 100 KB ≈ 20 MB of bodies plus
renders, doubling on first visit of each. `invalidatePreview` bounds it, so this is not a leak —
but it does not scale, and `tui-philosophy.md:41` promises low memory.
**Fix:** keep frontmatter plus body lines only for the selected skill; load the body lazily in the reload Cmd.

**D3 · Styled `view` output is unusable when piped (confirmed)**
A pty capture shows glamour emitting `ESC[38;5;252m ESC[38;5;252m SPACE ESC[0m` for **each padding
space** — roughly 40 escape sequences per filler cell. `skillman view x > out.md` or `| less`
produces a bloated, mangled file. `tui-philosophy.md:47` promises proper non-interactive output.
**Fix:** make the non-TTY path plain *by default* and add an explicit `--color=always` escape
hatch; that also removes the pty needed to test it.

**D4 · Rendering is fine — no action**
`View()` rebuilds and re-styles every row per frame at 20 fps; the glamour cache (`model.go:188`)
plus the spinner gate (`update.go:86`) removed the j/k lag. Measured behaviour was smooth in tmux.

### E · User experience

**E1 · Modals blank the entire screen and append a redundant line (confirmed)**
`view.go:361-386` — `overlay(under, modal, w, h)` **never reads `under`**. B11 is unfixed.
Live frame:

```
(5 blank lines)
               confirm delete
              +------ ... ------+
              |Delete skill "longbody"?  |
              ...
--- [Esc] close ---
```

The user loses all context, the modal does not say where the skill goes, and
`--- [Esc] close ---` contradicts `y confirm · n cancel`. The `under` parameter is dead code.
**Fix:** composite the modal onto a dimmed copy of the base frame; use or drop `under`; drop the trailing line.

**E2 · The help modal truncates the information the user needs (confirmed)**
`view.go:270` hardcodes `h = 20` and `box()` truncates each line (`view.go:320`). Live at 80×24:

```
|: command: edit delete validate reload clear …|
|Respects NO_COLOR, TERM=dumb, NO_ANIMATIONS, REDUCED_MOTI…|
```

Probe across heights:

```
height=24 NO_COLOR:true  delete to trash:true  open SKILL.md:true
height=18 NO_COLOR:false delete to trash:true  open SKILL.md:true
height=14 NO_COLOR:false delete to trash:false open SKILL.md:true
height=12 NO_COLOR:false delete to trash:false open SKILL.md:false
height=10 NO_COLOR:false delete to trash:false open SKILL.md:false
```

At 12 rows most of the keymap is gone, with no scroll and no "more below" hint. The box also
wastes 7 of its 20 rows on blank lines.
**Fix:** size the box to its content and make it a `viewport` so it scrolls.

**E3 · Preview focus is a navigation dead-end (suspected — code path)**
`update.go:183-197` routes `g G j k up down pgup pgdown ctrl+f ctrl+b d u f b space ctrl+d ctrl+u`
to the viewport. That leaves **no key that changes the selected skill** while the preview is
focused. Recoverable via `Tab`/`Enter`/`Esc`, but the user must guess. Note that `e`, `r`, `v`,
`/`, `:`, `?`, `q` still fire, so the "isolation" is arbitrary.
**Fix:** reserve `Tab`/`Enter`/`h`/`l` for pane switching and give the preview an unambiguous
prefix, or route `h`/`l`/`[`/`]` to pane focus.

**E4 · The status bar truncates the mode indicator (confirmed)**
`view.go:209` truncates `left + "  |  " + mod` to `m.width`. Live at 20×12: `skill-01 ·   |  nor…`.
`tui-philosophy.md:199` requires modes to be always visible — and this is exactly when it matters.
**Fix:** truncate `left` only; always render the full mode suffix.

**E5 · The frame is 78 of 80 columns and the right edge is ragged (confirmed)**
`view.go:65-67`: `lw + 1 + rw == m.width - 2`. Measured — header 80, panes 78, status 42, footer 71.
**Fix:** `lw = (m.width - 3) / 2; rw = m.width - lw - 3`.

**E6 · One terminal row is always wasted (confirmed)**
`model.go:257` `h := m.height - 4`; `View()` emits `1 + h + 1 + 1 = height - 1` lines.
Measured — 23 lines at height 24, 39 at height 40. B16 is only half-fixed.
**Fix:** `h := m.height - 3`.

**E7 · `q quit` disappears at exactly 70 columns (confirmed)**
`view.go:234` switches hints at `m.width < 70`; the wide hint is 71 cells (`view.go:237`) and
`truncate` (`view.go:240`) cuts it.

```
width=70 hasQuit=false  footer="… · ? qu…"
width=72 hasQuit=true
```

`TestFooterFits80` only asserts 80, so the suite cannot see it. B9's fix is incomplete.
**Fix:** make the hint set width-aware, or shorten the wide hint to ≤ 68 cells.

**E8 · `list` output is unusable for a long description (confirmed)**
`cli.go:42` `fmt.Printf("%-28s [%s] %s\n", …)` — a 400-char description prints in full, wraps
across terminal lines and destroys any line-oriented consumer.
**Fix:** truncate to a fixed width in the text path, or add `--long`.

**E9 · The confirm modal does not say what happens to the data (confirmed)**
`view.go:282` says "Moves to trash; undo with u within 30s" but not where, and `u` only works in
that one process. It should also name the failure mode: if the name reappears, undo refuses (`trash.go:50`).

**E10 · `e` on a skill with no `SKILL.md` opens a directory (confirmed by inspection)**
`editor.go:27-33` falls back to `s.Dir`. `vi <dir>` shows a file listing; saving cannot create
the missing file. **Fix:** offer to create `SKILL.md` from a template.

**E11 · No category column and no scroll indicator (confirmed)**
The live 80×24 frame shows `skills  /longbody` with no position, and `PLAN.md:109` lists
`5–19/40` as Phase 10 work that is not present. With 200 skills the user cannot tell where they are.

**E12 · `--help` documents no exit codes and there is no `--version` (confirmed)**
The contract (0/1/2/3) lives only in `cli_test.go:9` and `PLAN.md:49`. A script author has no
way to learn it. `skillman --version` does not exist.

**E13 · `list` is never coloured, so `--plain` is a no-op there (confirmed)**
`cli.go:12` `func runList(jsonOut, plain bool)` — `plain` is never referenced in the body. Dead
parameter; the TUI and `view` respect `NO_COLOR` but `list`/`validate` ignore styling either way.

**E14 · Documented deviations from `tui-philosophy.md` (confirmed by inspection)**
- `Ctrl-C` always quits rather than cancelling the current operation first (`update.go:117` vs
  `tui-philosophy.md:149`) — deliberate per audit B4, but undocumented.
- `?` types a literal `?` in filter mode instead of opening help (`update.go:142` vs `:176`).
- `Shift-Tab` and `Ctrl-P` are unbound (`update.go:234`) though both are in the baseline.
- `TERM=dumb` on a real TTY still takes over the screen with the alt screen; it only disables
  colour and the spinner (`config.go:48,67`). `tui-philosophy.md:34,251` treats it as a signal not to.
- The spinner flashes for a ~5 ms scan, violating "spinners only after 100–200 ms" (`:254`).
  `PLAN.md:27` admits it.

**E15 · JSON write errors are swallowed (confirmed by inspection)**
`cli.go:33,92` `_ = enc.Encode(rows)`. `skillman list --json | head -1` exits 0 with a truncated stream.

**F2 · `return m, m.doDelete()` relies on unspecified evaluation order (confirmed benign, real risk)**
`update.go:133,173,245,253,255,257` and `model.go:48`. I specifically probed this expecting state loss:

```
after 'y': appMode=0 undo.Active=true skills=1 toast="deleted live — u to undo"
after 'r': loading=true
after toastMsg: toast="hello toast" seq=1
```

**Disproven** — gc evaluates the call before the copy, so TUI delete/undo/rescan/toast all work
(also confirmed live in tmux). But the Go spec does not order non-call operands against calls, so
this is a latent trap. **Fix:** `cmd := m.doDelete(); return m, cmd`.

**F3 · Layout constants are still duplicated, which is what caused B2 (confirmed)**
`model.go:253-255` says layout and sizing "must share this one number" — but `view.go:65-67`
independently computes `lw`/`rw`, `view.go:61-63` computes `m.width-2`, and `model.go:213-219`
computes a third copy of the preview width. Four places encode the pane geometry.
**Fix:** one `layout` struct.

**F4 · `copyDir`'s `defer`s do not leak handles — disproven (confirmed benign)**
I suspected `trash.go:103,107` accumulated file descriptors across the walk.
Measured: `open fds before=6 after=6 (files=400)`. `defer` is scoped to the walk callback, which
returns per file. No change needed.

**F5 · Portability — disproven (confirmed builds)**
I expected `syscall.EXDEV` (`trash.go:9,67`) to break non-Unix builds. `GOOS=windows/amd64`,
`GOOS=darwin/arm64` and `GOOS=linux/arm64` all compile. Residual concern: on Windows `os.Rename`
across volumes returns `ERROR_NOT_SAME_DEVICE`, not `EXDEV`, so `movePath`'s fallback would not
trigger, and `os.Symlink` needs elevation. Low priority for a Termux tool, but `movePath` should
treat *any* rename failure as "try copy" rather than only `EXDEV`.

**F6 · `FilterSkills` returns the caller's slice (confirmed by inspection)**
`skills.go:170` — with an empty query, `m.filtered` and `m.skills` share one backing array, and

## R4 · Redesign — what I would build from scratch

The product goal: *a beautiful, trustworthy, keyboard-first tool for managing opencode skills,
usable equally well as a TUI and in a script.* Measured against that, the current code is a good
prototype with the wrong bones: the domain, the renderer and the CLI all reach into each other,
the layout arithmetic is smeared across four files, and severity is a string.

### R4.1 Architecture

```
cmd/skillman/          main.go — kong parser, exit-code mapping, nothing else
internal/skill/        Skill, Issue, Severity. Parse + validate + filter. Pure. No tea, no lipgloss, no os.
internal/store/        Load(dir), Trash(dir), Restore(). All os. Injectable root for tests.
internal/ui/           model.go (state + Update), layout.go (one layout func), views.go, keys.go (keymap table)
internal/render/       sanitize, display width, glamour cache, palette tokens
```

Why this beats the current structure: the six defects that keep recurring (A4, F3, A12, E5, E6, F8)
all share one cause — **the renderer recomputes geometry and re-derives domain facts instead of
reading them from a single owner.** A `layout` struct returned by one function and a `Severity`
enum owned by the domain make that class unrepresentable.

State lives in one `Model`; every side effect is a `tea.Cmd` returning a typed message. No method
may both mutate and do I/O.

Severity becomes data, not prose:

```go
// internal/skill/skill.go
type Severity int
const (SevOK Severity = iota; SevWarn; SevErr)

type Issue struct {
    Code string   // "frontmatter.malformed", "name.mismatch", "file.missing"
    Msg  string   // human text, never parsed back
    Sev  Severity
}

type Skill struct { Name, Desc, License, Compat, Category string; Issues []Issue; Body string }

func (s Skill) Severity() Severity          // max over Issues
func (s Skill) Badge() (string, Severity)  // "ok"/"warn"/"err" derived from Severity()
```

This deletes `Skill.Valid`, kills the `strings.HasPrefix(is, "missing SKILL.md")` coupling, fixes
**A3** (one pass over all issues, then map max severity → exit code) and makes **A6** impossible.

One layout owner:

```go
// internal/ui/layout.go
type Layout struct{ Header, List, Preview, Status, Footer Box; ListW, PrevW, BodyH int }

func Compute(w, h int) Layout {
    bodyH := max(h-3, 5)              // header + status + footer — fixes E6
    listW := (w - 3) / 2               // fixes E5 (78 -> 80)
    prevW := w - listW - 3
    return Layout{ListW: listW, PrevW: prevW, BodyH: bodyH, ...}
}
```

Both `Update` (viewport sizing) and `View` (box drawing) take this struct. **A12**, **F3** and the
whole B2 bug class are gone; `previewWidth()` disappears.

The untrusted-content boundary:

```go
// internal/render/sanitize.go
// Every string that came from a skill file passes through here before it
// reaches a terminal or a JSON encoder. Skill files are third-party input.
func Safe(s string) string {
    return escaper.Replace(s)   // \x00-\x08 \x0b-\x1f \x7f \x1b -> visible "\xNN"
}
func Width(s string) int { return runewidth.StringWidth(stripANSI(s)) }
```

Called once in `ScanSkills` on `Name/Desc/Category/Issues/Body`, so the TUI, the CLI and `--json`
are covered by construction. Fixes **C1** and **A1** together.

Selection and scroll become identity-based, killing A10/A11/F7:

```go
type Model struct {
    selected string            // skill name, not an index
    scroll   map[string]int    // per-skill preview offset
}
```

### R4.2 Interface design

**CLI principles:** one canonical keymap table; `--help` generated from it; subcommands as a typed
tree; stable documented exit codes; plain output by default when not a TTY.

```
skillman [global flags] <command> [args]

Commands:
  list      [--json] [--long]        list skills
  show      <name> [--plain]         print one skill
  validate  [--json] [--strict]      check frontmatter
  delete    <name> [--yes]           move to trash
  trash     list|restore <name>|purge [--older-than 30d] [--json]
  install   <git-url> [--ref]        install skills from a repo
  completion bash|zsh                shell completion
  help | version

Exit codes (also printed by --help):
  0 ok   1 validation issues   2 usage error / missing SKILL.md
  3 destructive without --yes  4 not installed on this build
```

Implemented with `github.com/alecthomas/kong` (struct tags → help, `--` support, subcommand type,
`--version` for free). It replaces the hand-rolled `switch` at `main.go:24-92` and removes **A7**,
**A8** and **A9** by construction. If a dependency is unacceptable, `spf13/cobra` is the
alternative; kong is smaller and generates terser help, which suits this tool.

**TUI keymap as data** — one table drives `Update`, the `?` overlay and `--help`, so the three
copies that `PLAN.md:123` wants cannot drift:

### R4.3 Data and state

`state.json` and `config.yaml` in `$XDG_CONFIG_HOME/skillman/`, written **atomically** (write temp
→ `fsync` → `rename`), versioned with a `schema` field, unknown fields tolerated. Trashed skills keep
their original name plus a monotonic sequence and a metadata sidecar (`orig_name`, `deleted_at`,
`reason`) so `trash restore` is exact and `purge --older-than` is implementable. Migration is
forward-only with a documented reset path.

### R4.4 Reliability and operability

Errors are values, never strings: `type OpError struct{ Op, Path string; Err error }` with
`Unwrap`. Every `tea.Cmd` returns a typed message; no path swallows an error (fixes **B1**, **B2**,
**E15**). Log through a size-capped rotating writer; log names, not paths.

### R4.5 Developer experience

- `make check` = `gofmt -l` + `go vet` + `staticcheck` + `go test -race ./...` + `scripts/smoke-tmux.sh`.
- **Golden frames** for a table of sizes — the highest-leverage single change:

```go
for _, sz := range []struct{ w, h int }{{20,10},{50,20},{70,24},{80,24},{120,40}} {
    for _, plain := range []bool{false, true} {
        t.Run(fmt.Sprintf("%dx%d/plain=%v", sz.w, sz.h, plain), func(t *testing.T) {
            assertMaxCellWidth(t, modelFor(sz).View(), sz.w)  // runewidth, not runes
            assertGolden(t, modelFor(sz).View(), sz, plain)
        })
    }
}
```

- `github.com/charmbracelet/x/exp/teatest` for key-driven model tests: send `/`, `zzz`, `Enter`,
  `d`, `y`, `u` and assert the resulting state. This alone covers the entire `update.go` gap (G1).
- `FuzzParseFrontmatter` seeded with the BOM/CRLF/thematic-break cases from A5.
- CI matrix: `stable` plus the `go.mod` minimum, `-race`, and `GOOS=windows/darwin/linux` build-only jobs.
